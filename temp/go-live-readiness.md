## 一、当前结论

Wanderline 的核心旅行计划、地点编辑、多日路线、Google Maps 地点搜索与三种交通方式导航已经实现，本地 Docker Compose、PostgreSQL/Flyway、后端测试、前端构建和浏览器端验收已经跑通。

当前版本适合继续进行内部验收或受控测试，**尚不满足公开正式上线要求**。主要阻断项如下：

- ⛔ 尚未确定并实现用户身份、数据归属和数据隔离；当前所有计划共用同一数据空间。
- ⛔ 只有本地 Docker Compose 配置，尚无生产域名、HTTPS、反向代理、生产 CORS 和部署方案。
- ⛔ 服务端 Routes API 未见鉴权或限流，公开后可能被滥用并产生 Google API 费用。
- ⛔ 生产密钥管理、数据库备份、恢复演练和回滚方案尚未建立。
- ⛔ 自动质量门槛已在本地实现，但尚未推送并取得远程 Actions、容器扫描、SBOM 和发布产物证据。
- ⛔ 尚无生产监控、错误告警和可回滚的部署流程。

如果仅上线为个人使用、且通过 VPN/IP 白名单限制访问，可将“用户系统”替换为网络层访问控制；公开给多名用户使用时，用户系统和数据隔离必须在上线前完成。

### 阶段 3：身份、安全与数据隔离

**目标**：防止数据越权、接口滥用、密钥泄露和非授权费用。

**当前完成情况：⛔ 未满足公开上线要求**

- ✅ 服务端错误默认不返回堆栈，响应带 Request ID。
- ✅ Google 浏览器密钥和服务端密钥用途已分离，真实 `.env` 已被 Git 忽略。
- ✅ JPA 使用 `ddl-auto: validate`，数据库变更由 Flyway 管理。
- ⬜ 当前没有用户、登录、会话、计划所有者或租户字段。
- ⬜ 计划 CRUD 和 Routes 代理接口未见身份鉴别、授权和按用户限流。
- ⬜ Docker Compose 带有本地默认数据库密码 `wanderline-local`，不能用于生产。
- ⬜ Actuator 暴露 `health`、`info` 和 `flyway`，尚未配置生产网络访问限制。
- ⬜ 尚无安全响应头、CSRF/滥用策略、审计日志和安全基线检查记录。

**上线要求**

- [ ] 公开多用户服务必须实现登录、会话失效、计划所有权和所有读写接口的数据隔离。
- [ ] 个人服务必须至少通过 VPN、SSO、反向代理认证或 IP 白名单限制访问。
- [ ] Routes 计算接口按用户/IP 设置速率限制、并发限制和每日额度保护。
- [ ] 所有生产密码和服务端密钥由部署平台 Secret 管理，不进入仓库、镜像、日志或前端产物。
- [ ] Google 浏览器密钥限制为正式域名及 Maps JavaScript API、Places API (New)。
- [ ] Google 服务端密钥限制为 Routes API 和生产服务器出口 IP，并设置预算告警和配额上限。
- [ ] 替换所有默认口令；数据库只允许应用所在私有网络访问。
- [ ] 限制 Actuator 仅供内部网络或监控系统访问，不向公网暴露 Flyway 信息。
- [ ] 配置 HTTPS、安全响应头、请求体大小限制，并完成基础 OWASP 检查。

**完成标准**：未登录或越权用户无法读取/修改他人数据，密钥不可从代码、日志、镜像或浏览器中获得，API 滥用有明确上限。

- [ ] 检查浏览器控制台、后端日志、监控和 Google Cloud 指标无新增严重错误。
- [ ] 发布说明、用户公告、支持渠道和已知限制已准备。
- [ ] 上线后至少观察 2 小时，并在 24 小时内复查错误率、费用和数据库状态。

**完成标准**：Go/No-Go 清单由产品和技术负责人共同确认，正式版本可用、可观察、可恢复、可回滚。

## 三、正式上线硬性门槛

以下任一项未满足时，不应进行公开正式上线：

1. **访问与数据安全**：存在未授权访问或跨用户读写风险。
2. **密钥与费用安全**：服务端密钥可能泄露，或 Routes API 无限流/配额保护。
3. **数据可恢复性**：没有自动备份，或备份从未成功恢复验证。
4. **生产网络**：没有 HTTPS，生产 CORS 仍允许 localhost 或任意来源。
5. **发布可靠性**：本地已有可重复自动测试，但尚无远程成功记录、已归档版本产物和回滚路径。
6. **故障发现能力**：服务异常、数据库异常或 Google API 大量失败时无人收到告警。
7. **用户可见质量**：仍有开发阶段文案、阻断性错误或核心流程无法完成。

## 四、建议的上线顺序

1. 先完成阶段 0，明确个人受限访问还是公开多用户。
2. 并行完成阶段 1 的界面收尾和阶段 3 的安全/数据隔离设计。
3. 建立阶段 6 的 staging 环境及阶段 7 的 CI，所有后续验收都在 staging 执行。
4. 完成阶段 4 的备份恢复、阶段 5 的生产 Google 配置和阶段 8 的监控告警。
5. 执行阶段 9 的 Go/No-Go 清单，再发布生产版本。

## 五、每次候选版本的复验命令

```bash
cd backend && ./mvnw -B test
cd ../frontend && npm ci && npm audit --audit-level=high
npm run lint && npm run build && npm run test:e2e:stability
cd ..
node --test scripts/performance-smoke.test.mjs scripts/require-env.test.mjs
scripts/run-performance-smoke.sh
docker compose config --quiet
docker compose build backend frontend
```

除自动化命令外，每个候选版本还必须完成生产等价环境冒烟、真实 Google API 小流量测试、数据库备份恢复验证和安全配置复核；仅本地测试通过不能作为正式上线依据。
